# 기획 변경 — 놀이공원에서 체리 농장으로

**작성일:** 2026-09-29
**상태:** 방향 확정. 기존 기획서 A-6-6(공원), A-8(게임화) 대체

---

## 1. 무엇을 바꾸나

**놀이공원 → 체리 농장.**

### 왜

| 이유 | 내용 |
|---|---|
| **이름과 맞는다** | 앱 이름이 체리인데 놀이공원은 이어지지 않는다. 체리 농장에서 체리를 수확하는 건 설명이 필요 없다 |
| **가공 체인이 생긴다** | 놀이공원은 "기구를 하나 더 놓는다"가 전부였다. 농장은 수확 → 가공 → 판매로 이어진다 |
| **확장이 가볍다** | 새 기구를 그리는 대신 레시피 한 줄을 추가한다 |
| **에셋 부담이 준다** | 관람차 대신 잼 병. 만들기도 쉽고 크기도 작다 |
| **날씨가 의미를 갖는다** | 놀이공원에서 날씨는 그냥 배율이었다. 농장에서는 작물이 자라는 조건이다 |

### 잃는 것

**"크게 짓는 쾌감."** 롤러코스터 타이쿤식 배치 재미는 줄어든다.
대신 **인접 효과와 꾸미기**로 배치 고민을 다른 방식으로 가져온다.

## 3. 핵심 구조 — 프로젝트가 밭 한 구획

```
프로젝트 "포트폴리오 리뉴얼"  →  밭 한 구획
   태스크 완료               →  그 밭의 작물이 자람
   마일스톤 완료             →  수확
   프로젝트 완료             →  나무로 승격. 계속 열매를 맺음
```

**농장이 곧 내 프로젝트 지도가 된다.** 밭을 보면 요즘 손 안 댄 프로젝트가 보인다.

**끝난 프로젝트는 나무가 되어 남는다.** 기획서 원칙 "완공된 것을 지우지 않는다"의 구현.
과거의 성취가 지금도 매일 체리를 준다.

---

## 4. 작물이 프로젝트 타입을 따라간다

| 프로젝트 타입 | 작물 | 동작 |
|---|---|---|
| **자유형** | 나무 | 마일스톤마다 한 번씩 수확. 여러 번 열림 |
| **진도형** (강의 20강) | 줄뿌림 작물 | 한 줄씩 차례로 익음. 진도가 눈에 보임 |
| **시험형** (D-47) | 수확일 고정 작물 | 그날 수확. 덜 자랐으면 수확량이 적을 뿐, **썩지 않는다** |

시험형이 특히 잘 맞는다. 실제로 시험날은 정해져 있고 준비가 덜 돼도 봐야 한다.

## 5. 가공 체인

```
[오늘 화면]  할 일 체크
      ↓
[농장]      해당 프로젝트 밭의 작물이 자람
      ↓
마일스톤 완료 → 수확 → 체리
      ↓
[가공]      레시피 선택          ← 유일한 선택 지점
      ↓
자동 완성 → 자동 판매 → 수익
      ↓
새 밭 · 새 레시피 · 시설 해금
```

**사용자가 손으로 하는 건 "체크"와 "뭘 만들지 고르기" 둘뿐.** 나머지는 전부 자동.

### 레시피

```
체리 + 설탕      → 체리잼
체리 + 우유      → 체리 라떼
체리잼 + 반죽    → 체리 파이
```

**행 하나 넣으면 콘텐츠가 하나 는다.** 에셋도 작은 아이콘 하나면 된다.

### 가공 시간

시간이 걸리게 하되 **확인하러 들어올 필요는 없다.**

- 완성되면 **자동으로 창고에 들어간다**
- 알림 없음
- **상하지 않는다.** 며칠 안 와도 그대로
- 주문·기한 없음. 만들어두면 알아서 팔린다

> 잼은 하루 숙성, 파이는 두 시간. 억지 대기가 아니라 요리라서 당연한 것으로 읽힌다.
> 그리고 내일 다시 열 이유가 된다. 단, **의무가 아니라 기대여야 한다.**

## 6. 계절과 날씨

기상청 API를 이미 쓰기로 했으므로 **실제 날씨와 계절이 그대로 들어온다.**

| | 농장에서 |
|---|---|
| 비 | 물을 안 줘도 됨. 성장 속도 ↑ |
| 맑음 | 수확량 ↑ |
| 봄 | 심기 좋은 계절. 새 프로젝트 보너스 |
| 여름 | 성장 빠름 |
| 가을 | 수확 보너스 |
| 겨울 | 밭은 쉬고 **가공에 집중** |

**어떤 계절에도 수확이 0이 되지 않는다.** 조금 줄어들 뿐. (원칙 4)

---

## 7. 도감 — 회고가 수집이 된다

```
체리잼      처음 만든 날   8월 12일
체리 라떼    처음 만든 날   8월 28일
체리 파이    ???
```

**각 항목에 "처음 만든 날"이 기록된다.** 도감을 넘겨보면 "8월에 이런 걸 했구나"가 나온다.

기획서 원칙 "정리를 안 해도 기록이 쌓인다"의 시각적 버전.

---

## 8. 주민

몇 명이 계속 찾아온다. 각자 취향이 있어서 좋아하는 걸 만들면 값을 더 쳐준다.
그것이 "뭘 만들지"의 힌트가 된다.

```
민지     라떼를 좋아함
할머니   잼을 좋아함. 가끔 씨앗을 줌
```

**요청은 소원이지 요구가 아니다.**

| 규칙 | 내용 |
|---|---|
| 기한 없음 | 언제 들어줘도 된다 |
| 누적 안 됨 | 한 번에 2~3개까지만 |
| 조용히 교체 | 오래된 건 말없이 사라지고 새 게 온다 |
| **호감도 하락 없음** | 안 만나도 관계가 나빠지지 않는다 |
| 진척도 표시 금지 | `(0/3)` 이 붙으면 숙제가 된다 |

**문구는 부탁이지 불평이 아니다. 그리고 한 문장.**

```
"라떼 한 잔 마시고 싶네요"        좋음
"요즘 통 안 오시네요"             나쁨
"잼 부족 (2/5)"                   나쁨
```

### 체리 잔액을 함께 보여준다

> 지금 체리 320개. 라떼는 바로 만들 수 있어요.

소원만 있으면 목록이다. **지금 얼마가 있고 얼마가 부족한지가 보여야** 오늘 체크할 동기가 생긴다.

---

## 9. 꾸미기 — 오래 머물러도 되는 유일한 곳

**농장에서 시간을 쓰는 건 허용한다.** 힐링이 목적 중 하나다.

- 밭·나무·시설 배치
- 울타리, 길, 장식물
- 계절 장식
- 인접 효과 — 벌통 주변 나무의 수확량 증가 같은 것

**배치 고민이 재미가 되게 한다.** 롤러코스터 타이쿤의 배치 재미를 여기서 가져온다.

### 다만 구분할 것

| | |
|---|---|
| **자발적으로 오래 있는 것** | 좋다. 꾸미고 배치하는 건 힐링 |
| **의무로 들어와야 하는 것** | 안 된다. 수확·물주기·청소 |

**"안 하면 손해 보는 것"만 없으면 된다.** 시간을 쓰는 것 자체는 문제가 아니다.

---

## 10. 절대 넣지 않을 것

| | 왜 |
|---|---|
| **물주기** | 매일 해야 하는 일. 할 일이 두 배가 된다 |
| **체력·기력** | 하루에 할 수 있는 양이 제한되면 압박 |
| **작물 시듦** | 며칠 안 오면 손해 = 죄책감 장치 |
| **주문 기한** | "3일 안에 잼 5개" |
| **호감도 하락** | 안 만나면 떨어지는 수치 |
| **잡초·청소** | 안 하면 지저분해지는 것 |
| **기능 잠금** | 체리로 살 수 있는 건 장식과 확장까지. 앱 기능은 잠그지 않는다 |

전부 **"안 하면 나빠지는 것"**이다.

> **농장은 들르면 반가운 곳이지, 돌봐야 하는 곳이 아니다.**

스타듀밸리에서는 물주기·체력·시듦을 가져오지 않는다. **동물의 숲 쪽 문법을 따른다.**
동숲의 핵심은 "안 해도 벌 받지 않는다"이고, 이것이 기획서 원칙 4와 같다.

## 11. 스키마

```sql
-- 작물·시설 마스터
CREATE TABLE crop_type (
  code        VARCHAR(50) PRIMARY KEY,
  name        VARCHAR(50)  NOT NULL,
  category    VARCHAR(20)  NOT NULL,   -- CROP | TREE | FACILITY | DECO
  sprite_key  VARCHAR(100) NOT NULL,
  tile_w      TINYINT NOT NULL DEFAULT 1,
  tile_h      TINYINT NOT NULL DEFAULT 1,
  price       INT     NOT NULL,
  season      VARCHAR(20) NULL
);

-- 농장 배치
CREATE TABLE farm_plot (
  id         BIGINT NOT NULL AUTO_INCREMENT,
  user_id    BIGINT NOT NULL,
  crop_code  VARCHAR(50) NOT NULL,
  project_id BIGINT NULL,              -- 프로젝트와 연결된 밭
  grid_x     TINYINT NOT NULL,
  grid_y     TINYINT NOT NULL,
  rotation   TINYINT NOT NULL DEFAULT 0,
  planted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_plot_user (user_id, grid_x, grid_y)
);

-- 재료 보유량
CREATE TABLE inventory (
  user_id  BIGINT NOT NULL,
  item_code VARCHAR(50) NOT NULL,
  amount   INT NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, item_code)
);

-- 레시피 마스터
CREATE TABLE recipe (
  code        VARCHAR(50) PRIMARY KEY,
  name        VARCHAR(50)  NOT NULL,
  sprite_key  VARCHAR(100) NOT NULL,
  minutes     INT     NOT NULL,        -- 가공 소요 시간
  sell_price  INT     NOT NULL,
  unlock_at   INT     NOT NULL DEFAULT 0
);

CREATE TABLE recipe_ingredient (
  recipe_code VARCHAR(50) NOT NULL,
  item_code   VARCHAR(50) NOT NULL,
  amount      INT NOT NULL,
  PRIMARY KEY (recipe_code, item_code)
);

-- 진행 중인 가공
CREATE TABLE production (
  id          BIGINT NOT NULL AUTO_INCREMENT,
  user_id     BIGINT NOT NULL,
  recipe_code VARCHAR(50) NOT NULL,
  started_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  done_at     DATETIME NOT NULL,
  collected   BOOLEAN NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_prod_user (user_id, done_at)
);

-- 도감
CREATE TABLE recipe_discovery (
  user_id     BIGINT NOT NULL,
  recipe_code VARCHAR(50) NOT NULL,
  first_made  DATETIME NOT NULL,
  total_count INT NOT NULL DEFAULT 1,
  PRIMARY KEY (user_id, recipe_code)
);
```

**포인트**

- `farm_plot.project_id` — 프로젝트와 밭을 잇는 칸. NULL이면 프로젝트 없는 자유 배치
- `UNIQUE (grid_x, grid_y)`를 걸지 않는다. **2x2 시설은 네 칸을 차지**하므로 대표 좌표만 저장하고 겹침 판정은 서버에서
- `crop_type`, `recipe`가 마스터 테이블 — **콘텐츠 추가가 행 하나**
- `production.collected`는 자동 수집이라 사실상 항상 1. 이력용으로만 둔다

## 12. 아트 방향

### 톤

**형태는 코지(둥글둥글), 채색은 페인터리(부드러운 그라데이션과 빛).** 외곽선 없음.

### 제작 — 트리포 + 렌더링

**트리포(Tripo)로 3D 모델을 생성**하고, 아이소메트릭으로 렌더링한 PNG를 쓴다.

```
트리포로 모델 생성 → .glb 다운로드 → 직교 투영으로 렌더링 → 투명 PNG
```

렌더링은 블렌더에서 한다. **모델링은 하지 않고 렌더링 기계로만 쓴다.**
씬(카메라·조명)을 한 번 잡아두면 이후에는 모델만 갈아끼우고 렌더 버튼만 누르면 된다.

| 항목 | 값 |
|---|---|
| 카메라 | 직교 투영(Orthographic) |
| 각도 | 30도 x 45도 |
| 배경 | 투명 PNG |
| 타일 기준 | 1칸 = 256px 폭 |
| 조명 | **모든 오브젝트 동일. 한 번 잡고 고정** |

조명이 제각각이면 한 화면에 놓았을 때 바로 티가 난다.

**주의:** AI 생성물은 매번 텍스처와 스타일이 달라진다. 트리포에서 받은 뒤 **재질을 우리 팔레트로 통일**해야 톤이 맞는다.

### 유니티는 쓰지 않는다

WebGL 빌드가 최소 5~15MB. 현재 앱 전체가 200KB다.
**농장은 탭 하나**인데 나머지가 전부 React다. 탭 하나 때문에 엔진을 넣는 건 과하다.

단, 유니티 에셋스토어의 2D 아트를 PNG로 추출해 쓰는 것은 가능. 라이선스 확인 필요.

### 웹 렌더러 — PixiJS

```
npm install pixi.js @pixi/react
```

SVG로는 목표 톤을 낼 수 없다. 프로토타입까지만 쓰고 실제 아트는 PNG로 간다.

### 임시 에셋 — Kenney Isometric Miniature Farm

```
https://kenney.nl/assets/isometric-miniature-farm
```

- **CC0** — 상업적 사용 가능, 출처 표기 불필요
- 30도 x 45도, 타일 256px — **우리 규격과 같아서 섞어 쓸 수 있다**
- **농장 팩이라 헛간·울타리·작물·나무가 전부 들어 있다.** 놀이공원과 달리 바로 쓸 수 있다

트리포로 만든 것이 쌓일 때까지 이것으로 채우고, 하나씩 교체한다.

### 교체가 쉬우려면

```
public/sprites/crops/
└── cherry_tree.png     ← Kenney 것 → 직접 만든 것으로 교체
```

**파일명만 같으면 코드는 고치지 않는다.** 스프라이트 경로는 코드가 아니라 `crop_type.sprite_key`에 둔다.

## 13. 요약

| 항목 | 결정 |
|---|---|
| **테마** | 놀이공원 → **체리 농장** |
| **핵심 연결** | 프로젝트 = 밭 한 구획. 완료하면 나무로 승격 |
| **작물** | 프로젝트 타입(자유·진도·시험)을 따라간다 |
| **루프** | 체크 → 성장 → 수확 → 가공 → 판매 → 확장 |
| **사용자 조작** | 체크 + 레시피 선택. 나머지는 자동 |
| **날씨·계절** | 기상청 API 연동. 어떤 계절에도 0이 되지 않음 |
| **도감** | 처음 만든 날이 기록 = 회고 자료 |
| **주민** | 취향으로 힌트. 호감도 하락 없음 |
| **꾸미기** | **시간을 써도 된다.** 힐링이 목적 중 하나 |
| **경계** | 자발적으로 오래 있는 건 OK. **의무로 들어와야 하는 건 금지** |
| **문법 출처** | 스타듀보다 **동물의 숲** — "안 해도 벌 받지 않는다" |
| **아트** | 트리포로 모델 생성 + 블렌더로 렌더링. 유니티 기각. Kenney로 시작 |
